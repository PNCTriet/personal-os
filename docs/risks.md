# Technical Risks

Likelihood/Impact: H/M/L. Ordered by exposure.

| ID | Risk | L | I | Mitigation |
|---|---|---|---|---|
| R-01 | **Scope creep / never shipping.** 9 domains, 8 phases, one small team; architecture work outruns daily use. | H | H | Phase 1 daily use at milestone M3 (~4 weeks, phase-1-plan.md) with an explicit cut list. Deferred tables stay deferred. Each phase has an exit demo. New domain only when a real query needs it. |
| R-02 | **Prompt injection → harmful action.** Email/Notion/GitHub text instructs the AI to send mail, move money, leak data. | H | H | EXECUTE/finance/SENSITIVE writes need server-side confirmation with stored args; AI cannot confirm; untrusted-content labelling; no chained EXECUTE; narrow tool set; Command Center treated as non-session actor. |
| R-03 | **Google OAuth constraints (personal @gmail.com — confirmed 2026-09-29).** No Internal app possible. External app in "Testing" ⇒ refresh tokens expire 7 days after consent (Calendar + Gmail together). Publishing with restricted Gmail scopes needs verification + annual CASA assessment. | H (certain) | M | ADR-013 accepted: stay in Testing, Founder as sole test user; `refresh_token_expires_at` + T-48 h banner + Phase 8 T-24 h reminder; one-click reconnect preserving `sync_state`; minimal incremental scopes (Calendar P2, Gmail P4; `gmail.readonly`+`gmail.compose` default, metadata/send-only alternatives); `invalid_grant` → `expired`, no retry storm. Residual: Google automation pauses if the Founder skips a reconnect. |
| R-04 | **Calendar sync correctness** (recurring events, timezones, conflicting edits, deleted events, 410 resync). | M | H | Expanded instances in bounded window, `syncToken` incremental sync, etag + last-writer-wins per event with loser in audit, 1:1 unique mapping, fixture-based adapter tests from recorded Google payloads. |
| R-05 | **Sensitive data exposure to LLM providers.** Tool results containing finance/relationship/email data leave our boundary. | M | H | Classification filter before any tool output; `sensitive.read` opt-in per token; minimal summaries; provider with no-training data terms; Command Center scope restrictions. |
| R-06 | **Service-role path bypasses RLS.** API-key/AI requests use the secret key; a missing `user_id` filter would be invisible with one user. | M | M | Repository base helper injects `user_id`; second-user integration test for every repository; secret key imported in one `server-only` file; RLS still protects the session path. Revisit (JWT-minting per request) if multi-user ever happens. |
| R-07 | **No DB transactions via supabase-js** → partial writes (mutation ok, audit failed; multi-row ops). | M | M | Atomic multi-row ops as SQL functions (RPC); invariants in constraints/triggers; audit failures logged with request id and alerted; ADR-003 alternative (direct Postgres + Kysely) if RPC count grows beyond ~10. |
| R-08 | **Polymorphic `external_references` integrity** (no FK on entity_id). | M | L | entity_type enum, hard-delete cleanup triggers (tested), unique mapping indexes, weekly orphan check query in P8. |
| R-09 | **Cold email deliverability & compliance** (domain reputation, spam law, unsubscribes). | M | H | Dedicated sending subdomain + SPF/DKIM/DMARC, warm-up, daily caps, suppression on bounce/complaint/unsubscribe enforced in domain logic, `List-Unsubscribe`, confirmation for campaign enrollment. |
| R-10 | **Serverless limits without background jobs** (sync or bulk ops exceed function timeouts until Phase 8). | M | M | Bounded sync windows, paginated incremental sync resumable via `sync_state`, on-demand triggers; introduce Vercel Cron only in Phase 8 with a concrete job list. |
| R-11 | **Token/key compromise** (TOKEN_ENCRYPTION_KEY, secret key, API key leak). | L | H | Per-env keys, key_version rotation procedure, API key expiry/rotation/revocation, GitHub secret scanning pattern, never log secrets (redaction tests), MFA on owner account, Vercel env access limited to Founder/Ivan. |
| R-12 | **Schema churn after real use** (domains redesigned in later phases). | M | M | Phase-scoped migrations, additive changes, views for derived data, deferred tables not created speculatively; breaking changes recorded as ADRs. |
| R-13 | **MCP auth for ChatGPT and Claude.ai/Desktop connectors requires OAuth 2.1**, larger than API-key auth. | M | M | Phase 1.5 slice targets Claude Code (bearer API key works) and the Claude static-header beta if available on the Founder's plan; OAuth at Phase 7 via Supabase OAuth server capability or minimal AS; permission layer unchanged. |
| R-14 | **Finance correctness** (currency exponents, rounding, transfers, VND/USD mix). | L | H | Integer minor units, per-account currency, no FX in v1 (per-currency summaries), property-based tests for calcs, monthly reconciliation view. |
| R-15 | **Vendor lock-in** (Supabase, Vercel). | L | M | Plain Postgres + SQL migrations, auth behind `src/lib/auth`, no Edge Functions, no proprietary queues; data export endpoint (P8). |
| R-16 | **Data loss** (single DB holding life data). | L | H | Supabase PITR/daily backups on paid plan, monthly `pg_dump` export to owner-controlled storage, soft delete + 30-day trash, append-only audit. |
