# Domain Model

DDD-lite: bounded contexts = code modules (architecture.md §4). Aggregates are small; cross-aggregate references are by
id only. "Table" = persisted in the proposed schema; "Derived" = computed (view/query); "Deferred" = modeled here,
not in the proposed schema until its phase.

## 1. Identity rules (spec §7)

| Rule | Detail |
|---|---|
| Primary identity | `uuid` (`gen_random_uuid()`), generated by DB, never reused, never shown as the only handle in UI. |
| Human codes | Optional, display/lookup handle. Only on **projects** and **tasks** in v1. |
| Project code | Owner-chosen, `^[A-Z][A-Z0-9]*(-[A-Z0-9]+)+$`, ≤32 chars, e.g. `HOWL-VTO-01` = `{ORG}-{KEY}-{NN}`. Unique per user **including deleted rows** (never reused). **Immutable** (trigger). |
| Task code | Assigned by DB trigger: `{project.code}-T{seq}`, seq zero-padded to 2 (`T01`…`T99`, then `T100`). Per-project counter `projects.next_task_seq` under row lock → no gaps from races, no duplicates. |
| Inbox tasks | Tasks without a project have no code until assigned. |
| Task moved to another project | Gets a new code in the new project; old code appended to `previous_codes` and still resolves on lookup (like Jira key redirects). A coded task cannot return to inbox. |
| Lookup | API/AI accept UUID **or** code wherever an id is accepted (`/tasks/HOWL-VTO-01-T01`). Resolution: UUID regex → id; else `code = $1 OR $1 = ANY(previous_codes)`. |
| Titles | Never identifiers. AI tools must resolve titles to ids via search and ask when ambiguous (ai-tools.md). |
| External IDs | Stored only as returned by the provider, in `external_references.external_id` (core entities) or intrinsic columns on delivery logs (`email_messages.provider_message_id`, `email_events.provider_event_id`, `webhook_deliveries.delivery_id`). Never invented, never used as primary keys. |

## 2. Data classification (spec §25)

| Level | Meaning | Default for | AI / API access |
|---|---|---|---|
| **PUBLIC** | Safe to publish (portfolio project, public bio). | nothing by default | Any read scope. Future public endpoints may expose. |
| **PRIVATE** | Normal personal data. | most rows | Domain `*.read` scope. Included in generic search. |
| **SENSITIVE** | Harm if leaked: romantic/family/health context, finance, private memories, email bodies. | all finance tables (domain rule, no column); `relationships.kind = romantic` (DB check); owner can mark any row | Requires domain scope **plus** `sensitive.read`. **Never** returned by generic/cross-domain search (`search_notes`, timeline, today) unless the caller holds `sensitive.read` and the tool explicitly requests it. Writes to sensitive rows by non-session actors require confirmation. |

Classification is a column (`data_classification` enum) on content tables; for finance it is implied by the domain.
Filtering happens in repositories (single `applyClassificationFilter(ctx)` helper), not in each route.

## 3. Bounded contexts and entities

### 3.1 Personal / Platform
| Entity | Storage | Notes |
|---|---|---|
| User | `auth.users` | Supabase Auth identity. **`users` table cut** — duplicating auth.users adds sync bugs. |
| Profile | `profiles` (1:1) | display name, timezone (defines "today"; default Asia/Ho_Chi_Minh), locale, base currency (VND), UI settings. |
| Preference | `memories(category=preference)` | Personal preferences are memories (time-aware, correctable). UI prefs = `profiles.settings`. |
| Goal | Deferred (`goals`, P6+) | Personal/career/fitness/learning goals. Financial goals separate (money semantics). Until then: `memories(category=goal)`. |
| Habit, Routine | Deferred (P8) | Needs scheduling/jobs. Routines as `calendar_events(kind=routine)` meanwhile. |
| Personal note | `notes` | Same table as knowledge notes. |
| Life event | `memories(category=life_event)` | Appears in timeline. Dedicated table only if richer shape needed. |
| API key | `api_keys` | Aggregate root; scopes, expiry, revocation. |
| AI action | `ai_actions` | Agent invocation + confirmation state machine. |
| Audit log | `audit_logs` | Append-only. |

### 3.2 Work
| Entity | Storage | Invariants |
|---|---|---|
| Company | `companies` | Unique domain per user. Clients = companies/people with a `client` relationship or linked projects; **no separate `clients` table**. |
| Project (AR) | `projects` | Immutable code; `completed` ⇔ `completed_at`; target ≥ start. |
| Task (AR) | `tasks` | `done` ⇔ `completed_at`; `follow_up` needs person/company; state machine below. |
| Task dependency | `task_dependencies` | No self/cycles (trigger). "Blocked" = has unfinished dependency (derived) **or** manual `blocked` status (external blocker). |
| Meeting | `calendar_events(kind=meeting)` | Not a separate table. |
| Deliverable | `tasks(kind=milestone)` | |
| Work log | Deferred | Derivable from `time_block` events + completed tasks; add `work_logs` only for billing. |

Task state machine: `backlog → todo → in_progress → done`; any open state ↔ `blocked`; any open state → `cancelled`;
`done → todo` (reopen, clears `completed_at`). Transitions validated in `work/domain.ts`; DB checks enforce the
`completed_at` pairing.

### 3.3 Time
| Entity | Storage | Notes |
|---|---|---|
| Calendar event | `calendar_events` | OS record; Google link via `external_references`. Recurring series stored as expanded instances in a sync window (ADR-014). |
| Time block | `calendar_events(kind=time_block, task_id)` | Project → Task → Calendar Event (spec §8). One task → many blocks. |
| Appointment | `calendar_events(kind=appointment)` | |
| Availability | Derived | Free/busy computed from events + working hours in `profiles.settings`. |

### 3.4 Finance (deterministic, never AI-computed)
| Entity | Storage | Notes |
|---|---|---|
| Finance account | `finance_accounts` | Renamed from `accounts`. One currency per account. |
| Transaction | `finance_transactions` | Signed `amount_minor` (bigint). Currency must equal account currency (trigger). Transfer = 2 legs sharing `transfer_group_id`, created atomically by `record_transfer()`. |
| Debt / Receivable | `debts(direction)` | **Merged**: identical shape. Outstanding = principal − repayments (inflows for receivable, outflows for payable) — view `debt_balances`. |
| Financial goal | `financial_goals` | Progress = linked account balance; no stored "current amount". |
| Balance | Derived | `finance_account_balances` view. Never stored. |
| Cashflow | Derived | Sum by period/category, per currency. |
| Budget | Deferred (P3) | `budgets(category, period, limit_minor, currency)`; spend derived. |
| Subscription | Deferred (P3) | `subscriptions(amount, cadence, next_due_on, account)`; P8 creates reminders. |

"How much can I spend this week?" = deterministic function in `finance/domain.ts`
(balances − upcoming known obligations − budget remainder), exposed as a service; the LLM only phrases the result.

### 3.5 Relationships (first-class)
| Entity | Storage | Notes |
|---|---|---|
| Person (AR) | `people` | Any human: friend, family, client contact, lead. **`contacts` cut** — one person table. Emails/phones as arrays (GIN). `email_opt_out_at` = outreach suppression. |
| Relationship | `relationships` | Owner ↔ person, one row per kind (a person can be friend **and** client). closeness 1–5. Romantic ⇒ SENSITIVE. Person↔person graph deferred. |
| Interaction | `interactions` | One person per row (v1 trade-off: group dinner = N rows). Optional link to event/email. |
| Important date | `important_dates` | month/day/(year) so birthdays without year work; person null = owner's own date. |
| Preference (about a person) | `memories(person_id, category=preference)` | |
| Shared experience | `interactions` + optional `memories(category=historical_context)` | Not a separate table. |
| Follow-up | `tasks(kind=follow_up, person_id)` | **`follow_ups` cut**: a follow-up *is* a task (due date, status, priority, reminders). Automated email follow-ups = `email_sequence_steps`. |
| Last contacted | Derived | `max(interactions.occurred_at)` per person. |

### 3.6 Communication
| Entity | Storage | Notes |
|---|---|---|
| Lead | `leads` | Pipeline state for a person/company. Contact data stays on `people`. |
| Campaign | `email_campaigns` | Resend only. |
| Sequence step | `email_sequence_steps` | Ordered steps with delay; the "sequence" is the campaign's steps (**no separate `sequences` table**). |
| Enrollment | `campaign_enrollments` | Lead in campaign; `current_step`, `next_send_at`. |
| Email message | `email_messages` | OS-originated outbound only (Resend + Gmail sends/drafts made by the OS). |
| Email event | `email_events` | Delivery/open/click/bounce; unique provider event id = webhook idempotency. |
| Gmail mailbox (threads, inbound) | **Not stored** | Queried live via Gmail adapter; referenced via `external_references` when linked to a task/person. Keeps sensitive mail out of our DB (ADR-021). |

Resend (outreach) and Gmail (mailbox) stay separate: separate adapters, separate scopes (`outreach.send` vs `gmail.send`),
shared only the `email_messages` log table (discriminated by `provider`).

### 3.7 Development / Growth — Deferred
Fitness, running, learning, languages, skills, career. Not in §10. Until a phase adds them: goals → `memories(goal)`,
milestones → `memories(life_event)` / notes, workouts → deferred `activities` table (type, started_at, duration, distance, metrics jsonb) when there is a data source (Strava/Health export).

### 3.8 Knowledge
| Entity | Storage | Notes |
|---|---|---|
| Note / research / bookmark / document | `notes(kind)` | Markdown body, tags, FTS (`simple` config — Vietnamese + English). Documents = metadata + URL until object storage is justified. |
| Topic | `notes.tags` | No topic table in v1. |
| Source | `notes.source_url` | |
| Notion reference | `external_references(external_type=notion_page)` | Notion is not the source of truth. |

### 3.9 Memory (spec §26)
Structured, typed, time-aware facts. **No global blob.** Correction = insert new memory with `supersedes_id`, set old
`valid_until = now()`. Expiration = `valid_until`. AI-created memories: `source=ai`, `confidence < 1`, `source_ref =
ai_action id`; requires `memory.write`. Current memory = `valid_until IS NULL OR valid_until > now()`.

### 3.10 Integrations
| Entity | Storage |
|---|---|
| Provider catalog (google, notion, github, resend: capabilities, scopes, adapter) | **Code**, not a table (`integrations/core/catalog.ts`). `integrations` table cut. |
| Integration account | `integration_accounts` |
| Credentials | `integration_secrets` (encrypted, service-role only) |
| External reference | `external_references` |
| Webhook delivery | `webhook_deliveries` |

### 3.11 Timeline (spec §27)
`timeline_events` view unions domain facts (project created, task completed, income, meeting, interaction, life event).
New sources are added to the view, never hand-entered. Carries `classification` so SENSITIVE rows are filtered.

## 4. Cross-domain links (spec §8)
Task → project, person, company (FK); task → calendar event (via `calendar_events.task_id`, 1:N);
task → GitHub issue / Notion page (via `external_references`). Notes/memories → person/project (FK).
Finance → person/company as counterparty (FK). Interactions → calendar event / email message (FK).
